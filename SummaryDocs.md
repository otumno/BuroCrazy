# АРХИТЕКТУРА ПРОЕКТА И ПОТОК ДАННЫХ

---

**Цель:** Обеспечить стабильность при масштабировании и переходе между сценами.

**Core Systems:**

1. **Bootstrapper:** Префаб [SYSTEMS]. Инициализируется в первой загруженной сцене. Содержит все менеджеры.
2. **Singleton Pattern:** Все менеджеры (HiringManager, DirectorManager, TimeManager) — синглтоны с защитой от дубликатов (DontDestroyOnLoad).
3. **Scene Management:**
   - TransitionManager: Управляет загрузкой сцен и фейдом (листья).
   - SceneAutoLoader (Editor Only): Позволяет запускать игру с любой сцены, автоматически подгружая менеджеры.

**Связи:**

- UI **не содержит** логики. UI дергает методы Менеджеров. Менеджеры обновляют Данные. UI подписывается на события Данных (Action / Event).

# СТРУКТУРА ИГРЫ И ЮЗЕРФЛОУ

---

**Цель фичи:** Обеспечить понятную навигацию между состояниями игры, исключить тупиковые экраны и определить точки сохранения.

**Общее описание:** Игра состоит из четырех основных сцен/состояний: Главное Меню, Офис (Геймплей), Карта (Мета-игра) и Пауза. Переходы между ними сопровождаются анимацией (листья/затемнение).

**Описание по деталям:**

1. **Launch:** Splash Screen "Bureau Crazy" -> Главное Меню.
2. **Main Menu:**
   - *Новая игра:* Выбор слота -> Старт.
   - *Загрузка:* Выбор слота -> Офис (состояние сохраненного дня).
3. **Gameplay Loop (Scene: GameScene):**
   - *Start Of Day (UI):* Панель подготовки (Найм, Приказы).
   - *Action (Sim):* Управление Директором и камерой.
   - *End Of Day (UI):* Экран итогов (Страйки, Деньги).
   - *Map (UI/Overlay):* Глобальная стратегия (между днями или по вызову).
4. **Pause Menu:** Вызывается ESC. Опции: Продолжить, Настройки, Выход в Меню (с автосохранением).

**Техническая реализация:**

- **Менеджер:** MainUIManager (Singleton) управляет состояниями.
- **Переходы:** TransitionManager отвечает за загрузку сцен и анимацию "падающих листьев".
- **Сцены:** MainMenuScene и GameScene.

# КЛИЕНТЫ

---

**Цель фичи:** Вариативность геймплея. Игрок визуально считывает угрозу и реагирует.

## Общее описание

**Клиентская система** управляет всеми посетителями офиса — от момента спавна до ухода.

### Ключевые особенности:
- **Жизненный цикл**: Клиент проходит от спавна до выхода через несколько этапов
- **State Machine**: Машина состояний управляет поведением клиента
- **Терпение**: У каждого клиента есть таймер терпения, по истечении которого он уходит
- **Цели визита**: Разные цели ведут к разным зонам офиса
- **Архетипы**: Влияют на скорость, терпение и поведение клиента
- **Интеграция с зонами**: Клиенты используют LimitedCapacityZone для очередей

### Как клиент влияет на геймплей:
- Клиенты создают очередь — нужно назначать сотрудников к окнам
- "Сложные" клиенты (ярость, замешательство) требуют внимания
- Некоторые клиенты платят больше, некоторые создают беспорядок
- Ушедшие злые клиенты могут оставить негативный отзыв

### Отличия от документации:
⚠️ Архетипы "Бабушка", "Суетун", "Мажор", "Пролаза" — **концептуальные**, в коде реализованы через `babushkaFactor` и `suetunFactor`
- Функция "VIP/двойная оплата" — **не реализована** в текущем коде
- Функция "пролаз без очереди" — **концептуальная**, prolazaFactor не используется активно

## Система Клиентов

### Жизненный цикл клиента

```
Spawning → AtRegistration → AtDesk → AtCashier → Leaving → Destroy
                ↓
         VisitToilet ──────────────────────→ Returning to Goal
                ↓
         WaitingForDocument → AtCashier → Leaving
                ↓
         InsideLimitedZone → DirectorService → Leaving
```

### Клиентские состояния (ClientState)
- `Spawning` - Спавн
- `MovingToGoal` - Движение к цели
- `InQueue` - В очереди
- `WaitingForDocument` - Ожидание документа
- `AtRegistration` - У регистратуры
- `AtDesk1`/`AtDesk2` - У окон 1-2
- `AtCashier` - У кассы
- `InsideLimitedZone` - В зоне директора
- `Leaving` - Уход (успех)
- `LeavingUpset` - Уход (расстройство)
- `Confused` - Замешательство (потерял цель)
- `Enraged` - Ярость

### Цели визита (ClientGoal)
1. **GetCertificate1** - Справка 1 (Окно 1)
2. **GetCertificate2** - Справка 2 (Окно 2)
3. **PayTax** - Оплата налога (Касса)
4. **AskAndLeave** - Спросил и ушёл
5. **VisitToilet** - Туалет
6. **GetArchiveRecord** - Запрос в архив
7. **DirectorApproval** - У директора

## Архетипы

### Факторы влияющие на поведение:
- **babushkaFactor** (0-1): Замедляет, повышает терпение
- **suetunFactor** (0-1): Ускоряет, понижает терпение

### Характеристики:
- `totalPatienceTime` - Время до ухода
- `stressMultiplier` - Множитель стресса
- `noiseTolerance` - Толерантность к шуму
- `corruption` - Склонность к взяткам

- `Assets/Scripts/ClientStateMachine.cs` - Машина состояний
- `Assets/Scripts/Managers/ClientSpawner.cs` - Спавн
- `Assets/Scripts/Managers/ClientSpawnerWithArchetypes.cs` - Спавн по архетипам
- `Assets/Scripts/Managers/ClientQueueManager.cs` - Управление очередью

### Взаимодействие с зонами (LimitedCapacityZone)
- Клиент присоединяется к очереди зоны
- При вызове подходит к окну
- При уходе освобождает место

# ПЕРСОНАЛ

---

**Цель фичи:** Управление сотрудниками с учётом характеристик, навыков и потребностей.

## Общее описание

**Система персонала** управляет всеми сотрудниками офиса — от найма до увольнения.

### Ключевые особенности:
- **Ролевая система**: Разные роли имеют разные специализации и действия
- **Навыки**: 5 характеристик (0.0-1.0) влияют на эффективность работы
- **Потребности**: Динамические параметры (мочевой пузырь, энергия, мораль, стресс)
- **Смены**: Битовая маска определяет в какие периоды работает сотрудник
- **Перерывы**: Автоматические и ручные перерывы для восстановления потребностей
- **ИИ сотрудника**: ActionExecutor выбирает лучшее действие на основе приоритетов

### Как персонаж влияет на геймплей:
- Клерки обрабатывают документы — скорость зависит от навыков
- Охранник ловит нарушителей — снижает шанс краж
- Уборщик чистит беспорядок — предотвращает штрафы
- Кассир может красть деньги — зависит от corruption навыка
- Сотрудники с низкой моралью грубят клиентам

### Отличия от документации:
⚠️ Действия CoverDesk, DeliverDocuments, HelpConfusedClient, Patrol, CatchThief — **частично реализованы**
- Система "unwrittenReportPoints" для охранника — **концептуальная**, не полностью реализована
- Действие SystematizeArchive — **не найдено** в коде

## Характеристики (CharacterSkills)

### Навыки (0.0 - 1.0):
- **paperworkMastery** - Бюрократия (скорость документов)
- **sedentaryResilience** - Усидчивость (реже перерывы)
- **pedantry** - Педантичность (качество проверки)
- **softSkills** - Коммуникация (скорость обслуживания)
- **corruption** - Коррупция (шанс кражи)

### Влияние на геймплей:
- Высокий `paperworkMastery` = быстрее обрабатывает документы
- Высокий `pedantry` = чаще замечает ошибки/грязь
- Высокий `corruption` = чаще крадёт деньги

## Потребности (Needs)

### Динамические параметры:
- **Bladder** (0-1) - Мочевой пузырь
  - Рост: +0.05 каждые 10 сек
  - Критический порог: > 0.7 → уходит в туалет
  
- **Energy** (0-1) - Энергия
  - Спад: -0.02 каждые 10 сек (зависит от усидчивости)
  - Критический порог: < 0.3 → замедляется
  
- **Morale** (0-1) - Мораль
  - Спад: -0.03 каждые 10 сек
  - Эффект: Низкая мораль = грубость клиентам
  
- **Frustration** (0-1) - Стресс
  - Рост: От сложных клиентов и шума
  - Критический порог: 1.0 → истерика или увольнение

# ДИАЛОГОВАЯ СИСТЕМА

---

**Цель фичи:** Интерактивные диалоги с клиентами, NPC и сюжетные события с визуальным сопровождением.

## Общее описание

**Диалоговая система** — это графовая система интерактивных диалогов, используемая для взаимодействия директора с клиентами, NPC и для сюжетных событий.

### Ключевые особенности:
- **Графовая структура**: Диалог строится как направленный граф нод
- **Ветвление**: ChoiceNode позволяет создавать разветвлённые диалоги с условиями
- **Условия**: Система флагов (SetFlag) для сохранения состояния диалога
- **Визуальное сопровождение**: Поддержка изображений и фонов
- **Аудио**: Звуки при появлении реплик и событиях
- **Интеграция с геймплеем**: EventNode может изменять деньги, выдавать страйки

### Где используется:
- Диалоги с клиентами (при вызове в кабинет)
- Сюжетные события
- Инструктаж при найме
- События проверки

### Ограничения:
- Диалог блокирует геймплей (пауза)
- Требует настроенный UI (DialogueUIConnector)
- Изображения должны быть в проекте как Sprite

## Структура Нод

### Start Node (СТАРТ)
- Начальная точка диалога
- Поле `Default Background`: Фон по умолчанию для всех последующих нод
- Поле `Start Sound Override`: Кастомный звук начала диалога
- Выход: `nextNode`

### Phrase Node (ФРАЗА)
- Базовая реплика персонажа
- Поля:
  - `Speaker ID`: 'Director', 'Client' или ID из базы NPC
  - `Appear Sound`: Звук "вжик" при появлении
  - `Voice Clip`: Спец. озвучка
  - `Speaker Portrait`: Спец. портрет (переопределяет дефолтный)
  - `Node Image`: Изображение для показа в этой ноде
- Выходы: `nextNode`, `choices` (динамические)

### Choice Node (ВЫБОР)
- Ветвление диалога кнопками
- Поля:
  - `Query Text`: Вопрос игроку
  - `Options`: Список вариантов с условиями
  - `Node Image`: Изображение для показа
- Условия (Condition):
  - `Key`: Ключ флага (например: 'MONEY', 'MET_INSPECTOR')
  - `Op`: Оператор (>=, <=, ==, !=)
  - `Value`: Значение для сравнения

### Event Node (СОБЫТИЕ)
- Изменение состояния игры
- Поля:
  - `Set Flag Key`: Имя флага
  - `Set Flag Value`: Значение
  - `Add Money`: Добавить/отнять деньги
  - `Add Strike`: Выдать страйк директору
  - `Notification Text`: Текст окна "РЕЗУЛЬТАТ"
  - `Sound Effect`: Звук события
  - `Node Image`: Изображение для показа
- Выход: `nextNode`

### End Node (КОНЕЦ)
- Завершение диалога
- Выход: Нет (диалог закрывается)

### Random Node (РАНДОМ)
- Случайный переход к одной из нод
- Выходы: `randomOutputs`

### Condition Node (УСЛОВИЕ)
- Проверка флага и выбор ветки
- Выходы: `trueNode`, `falseNode`

## Логика Изображений

### Приоритет отображения:
1. Изображение в конкретной ноде (Phrase/Choice/Event)
2. Дефолтный фон из StartNode
3. Ничего (если не указано)

### Настройка UI:
```

├── Panel
├── DirectorPortraitImage

- Frame должен быть выше в иерархии (Z-index)

# PROGRESSION MANAGER — СИСТЕМА ПРОГРЕССА

---

**Цель фичи:** Централизованное управление прогрессом игрока (регионы, должности, влияние).

## Общее описание

**ProgressionManager** — центральный синглтон, хранящий состояние прогресса игрока и управляющий эффектами от проектных документов.

### Ключевые особенности:
- **Влияние (Influence)**: Новая валюта для карты и карьеры
- **Открытые регионы**: Список захваченных регионов
- **Открытые должности**: Список полученных должностей
- **Слушатель событий**: Реагирует на попадание документов в Архив

### Источники Влияния:
- Успешное обслуживание клиентов (+1-5)
- Положительные отзывы (+10)
- Захват региона (+100)
- Получение должности (+50)

## Структура Данных

### ProgressionManager:
- `currentInfluence` - Текущее влияние
- `unlockedRegionIDs` - Список открытых регионов
- `unlockedJobIDs` - Список открытых должностей
- `allRegionsDatabase` - База данных регионов
- `allJobsDatabase` - База данных должностей

### RegionData:
- `regionId` - Идентификатор
- `displayName` - Отображаемое имя
- `unlockCostInfluence` - Стоимость во влиянии
- `unlockCostMoney` - Стоимость в деньгах
- `clientSpawnRateMultiplier` - Множитель спавна
- `unlockNewArchetypes` - Новые архетипы

### JobTitleData:
- `jobId` - Идентификатор
- `titleName` - Название должности
- `tierLevel` - Уровень карьеры

```

# ХАРАКТЕРИСТИКИ И ПОТРЕБНОСТИ РАБОТНИКОВ

**Цель фичи:** Превратить сотрудников из функций в "тамагочи", за которыми нужно ухаживать, создавая глубину менеджмента.

**Общее описание:** Каждый StaffController имеет набор статических навыков (определяют эффективность) и динамических потребностей (определяют поведение).

**1. Навыки (Skills):** *Значения от 0.0 до 1.0. Задаются при найме (HiringManager), растут с опытом.*

- **Коммуникация (SoftSkills):** Скорость обслуживания клиентов.
- **Коррупция (Corruption):** Скрытый навык. Шанс украсть деньги.

**2. Потребности (Needs):** Динамические параметры 0.0-1.0.

- **Мочевой пузырь (Bladder):** При >0.7 → уходит в туалет.
- **Энергия (Energy):** При <0.3 → замедляется.
- **Мораль (Morale):** Низкая = выше шанс грубости.
- **Стресс (Frustration):** При 1.0 → истерика или увольнение.

## 2. Behavior Tree для Клиентов

**Цель:** Заменить текущую State Machine на модульную Behavior Tree для более гибкого и расширяемого поведения клиентов.

### Что добавлено:

**Базовые классы BT:**
- `BTNode` - базовый класс для всех узлов
- `BTNodeResult` - Success/Running/Failure
- `BehaviorTree` - менеджер дерева с тиками

**Composite узлы:**
- `BTSequence` - выполнение по порядку (все дети должны успех)
- `BTSelector` - выбор (первый успешный)
- `BTParallel` - параллельное выполнение

**Decorator узлы:**
- `BTInvert` - инвертирует результат
- `BTRepeat` - повторяет N раз
- `BTTimeout` - таймаут выполнения
- `BTCooldown` - задержка между выполнениями

**ClientBehaviorTree:**
- `ClientBehaviorTreeFactory` - фабрика для создания дерева

**Интеграция:**

### Структура дерева клиента:
