# Bureau Crazy — Техническая Архитектура

---

## Архитектура Проекта и Поток Данных

### Цель:

Обеспечить стабильность при масштабировании и переходе между сценами.

### Core Systems:

1. **Bootstrapper:** Префаб [SYSTEMS]. Инициализируется в первой загруженной сцене. Содержит все менеджеры.

2. **Singleton Pattern:** Все менеджеры (HiringManager, DirectorManager, TimeManager) — синглтоны с защитой от дубликатов (DontDestroyOnLoad).

3. **Scene Management:**
   - TransitionManager: Управляет загрузкой сцен и фейдом (листья)
   - SceneAutoLoader (Editor Only): Позволяет запускать с любой сцены, подгружая менеджеры

### Связи:

```
UI не содержит логики
     ↓
UI дёргает методы Менеджеров
     ↓
Менеджеры обновляют Данные
     ↓
UI подписывается на события Данных (Action / Event)
```

| **AssignmentManager** | Назначение на станции |
| **OfficeManager** | Управление офисом, мебелью |

### Паттерн:

```csharp
public class SomeManager : MonoBehaviour
{
    public static SomeManager Instance { get; private set; }
    
    void Awake()
    {
        if (Instance != null && Instance != this)
        {
            Destroy(gameObject);
            return;
        }
        Instance = this;
        DontDestroyOnLoad(gameObject);
    }
}
```

## Система Действий

### Паттерн: Command / Strategy

**Компоненты:**

1. **StaffAction (ScriptableObject):**
   - Условия выполнения
   - Приоритет
   - Ссылка на Исполнителя

2. **ActionExecutor (MonoBehaviour)::**
   - Логика выполнения (корутина)
   - Создаётся динамически (AddComponent)

### Цикл принятия решений:

```
StaffController:
    ↓
Раз в N секунд (или по событию)
    ↓
Проверяет activeActions + systemActions
    ↓
Выбирает действие с наивысшим Score
    ↓
Запускает Executor
```

### Пример:

```csharp
// StaffController
public void Update()
{
    if (Time.time - lastDecisionTime > decisionInterval)
    {
        var bestAction = SelectBestAction();
        StartCoroutine(bestAction.Execute());
    }
}
```

## Оптимизация

### Основные принципы:

1. **Object Pooling:** Переиспользование объектов клиентов
2. **LOD:** Level of Detail для визуалов
3. **Batching:** Объединение отрисовки
4. **Culling:** Отключение невидимых объектов

### Особенности:

- Минимум 2 ГБ оперативы
- Хорошие процессоры и видеокарты
- Не ориентировано на мобилки

## ClientSpawner — Разделение

### SingleDayTimeSystem:

- Конфиг 1 календарного дня
- Сортировка периодов Night=>Morning=>...=>Evening
- Запуск по порядку
- Следит за временем, инкрементит, кидает эвенты

### CalendarSystem:

- Управление сменой дня
- dayIndex
- Загрузка настроек нужного дня
- Запуск событий (rand or scripted)

### CalendarDayPeriodType:

- Morning, EarlyDay, Noon, Day, Evening, Night
