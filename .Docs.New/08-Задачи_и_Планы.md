# Bureau Crazy — Задачи и Планы

---

## Главная проблема текущей архитектуры

### Проблема: Высокая связность

Все скрипты смотрят друг в друга. Добавление нового скрипта заставляет его связываться со всеми остальными. Связность растёт экспоненциально.

### Решение: Дробление на мелкие части

Каждая часть за что-то своё отвечает и избегает зависимости между ними.

**Принцип "ёлочки":**
```
Менеджер
    ↓
Система
    ↓
Компонент
    ↓
Данные
```

### UI:

UI управляется из манагеров → нужно написать отдельные UI скрипты, которые сами смотрят в нужные менеджеры.

## Раздробить ClientSpawner

### SingleDayTimeSystem:

- Конфиг 1 календарного дня
- Сортировка периодов Night=>Morning=>...=>Evening
- Запуск по порядку
- Следит за временем, инкрементит, кидает эвенты окончания

### CalendarSystem:

- Управление сменой дня
- dayIndex
- Подгрузка настроек нужного дня → в SingleDayTimeSystem
- Запуск событий (рандомные или прописанные)

### Инициализация:

- Сейчас в MainUIManager
- UI живёт сам по себе
- Инициализация из сохранений

## Звуковая Система

### AudioManager:

- Инициализация аудиомиксера
- Пул из 30 объектов с AudioSource
- Метод PlaySound()

```csharp
AudioManager.PlaySound("button_click");
```

### Зачем:

- Звуки доигрывают после уничтожения объекта
- UI звуки централизованно
- Перформанс (не вешать AudioSource на каждую кнопку)
