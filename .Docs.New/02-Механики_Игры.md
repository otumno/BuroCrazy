## Система Клинчей (Clinch Resolution)

### Общее описание

**Система клинчей** — это мини-игра для разрешения конфликтных ситуаций между персонажами (клиентами и сотрудниками). Когда персонаж находится в критическом состоянии (скандал, истерика), запускается таймер, по истечении которого происходят негативные последствия. Игрок должен успеть кликнуть на персонажа и выбрать правильный вариант.

### Механика:

1. **Триггер:** Персонаж входит в состояние клинча → `TriggerClinch()`
2. **Предупреждение:** Над головой появляется анимация (3 кадра), частота увеличивается по мере уменьшения таймера
3. **Таймер:** `clinchTimeoutDuration` из `AIBalanceConfig`
4. **Мини-игра:** Игрок кликает на персонажа → открывается UI с 3 кнопками-ключами и замком
5. **Выбор:** Замок имеет цвет (0-Красный, 1-Желтый, 2-Фиолетовый). Игрок должен нажать правильный ключ
6. **Результат:**
   - **Успех:** Персонаж успокаивается, позитивная фраза
   - **Провал/Таймаут:** Негативные последствия (скандал, уход, штраф)

### UI Мини-игры:

```
     [ЗАМОК]
    (цвет замка)

 [Ключ1] [Ключ2] [Ключ3]
   🔑       🔑       🔑
```

- Ключи перемешаны (Фишер-Йейтс)
- При нажатии: +0.5сек задержка → показывается результат (+ или -)
- Звуки: Success / Fail

### Реплики (из кода):

| Персонаж | Успех | Провал |
|----------|-------|--------|
| **Сотрудник** | "ААА вот как оно делается!", "Спасибо Шеф!", "Век живи - век учись!" | "Я так и знал...", "Мне никто не поможет...", "Всё пропало!" |
| **Клиент** | "Сразу надо было к вам!", "Отличный сервис!", "Премного благодарен!" | "Полная некомпетентность!", "Я буду жаловаться!", "Безобразие!" |

### Компоненты:

| Компонент | Файл | Описание |
|-----------|------|----------|
| **ClinchTarget** | `Assets/Scripts/Clinch/ClinchTarget.cs` | Логика клинча, таймер, анимация |
| **ClinchLocalUI** | `Assets/Scripts/Clinch/ClinchLocalUI.cs` | UI мини-игры (замок + ключи) |

## Документооборот и Работа Архива

### Жизненный цикл документа

Документ — это физический объект в мире игры. Он рождается в руках клиента, трансформируется на столе клерка, превращается в деньги в кассе и умирает в архиве.

```
Клиент → Регистратура → Обработка (Клерк) → Оплата (Касса) → Уход
```

### Этапы обработки:

1. **Вход:** Клиент спавнится с DocumentType в руках
2. **Регистратура:**
   - Регистратор проверяет цель клиента
   - Если нужна справка из архива — создаётся ArchiveRequest
3. **Обработка (Клерк):**
   - Клиент кладёт Бланк на стол
   - Клерк проверяет тип. Если неверен → Клиент отправляется за правильным
   - Клерк работает (таймер зависит от навыка)
   - Бланк уничтожается → Спавнится Certificate → "Летит" в руки клиенту
   - Копия добавляется в DocumentStack на столе
4. **Оплата:** Клиент идёт в кассу с Сертификатом
5. **Логистика:** Если DocumentStack полон → Стажер/Директор относит в Архив

### Типы документов:

| Категория | Описание |
|-----------|---------|
| **Cat 0** | Справки в регистратуре (платные/бесплатные), выписки из архива |
| **Cat 1** | Субкатегории: свидетельства, договоры, утверждения, докладные |
| **Cat 2** | Требуют доп. оборудования: копир, сшиватель, штампователь, суперпечати |

### Ограничения:

- DocumentStack имеет maxStackSize
- При полной стопке стол блокируется
- Стажер или игрок должен отнести стопку в Архив (DeliverDocumentsAction)

## Behavior Tree Клиентов

### Структура дерева:

```
ClientBehaviorTree (Selector)
├── TryMainGoal (Sequence) — главный путь
│   ├── GoToRegistration
│   ├── WaitInQueue
│   ├── GetServed
│   └── LeaveSuccess
├── TryAlternativePath — альтернативы
│   ├── QueueTooLong → TryCutInLine → DirectorComplain
│   └── NoService → DirectorComplain → LeaveUpset
├── GrumblingBehavior — управление недовольством
│   ├── PatienceBelowThreshold → Grumble
│   └── EscalateToEnraged / LeavingUpset
└── LeaveBehavior — завершение
```

### HeatLevel (уровни терпения):

```csharp
public enum HeatLevel
{
    Calm,        // 0-30%
    Grumbling,   // 30-70%
    Frustrated,  // 70-90%
    Enraged      // 90-100%
}
```

### Примеры поведения по архетипу:

| Архетип | Терпение | Ворчание | Эскалация |
|---------|----------|----------|-----------|
| **Суетун** | Ниже | Редко | Быстро |
| **Бабушка** | Выше | Часто | Медленно |

## Система Действий (Action System)

### Паттерн: Command / Strategy

**Структура:**

1. **StaffAction (ScriptableObject):** Описание действия (Условия, Приоритет, Ссылка на Исполнителя)
2. **ActionExecutor (MonoBehaviour):** Логика выполнения (Корутина). Создаётся динамически
3. **Цикл принятия решений:**
   - Раз в N секунд проверяет доступные activeActions + systemActions
   - Выбирает действие с наивысшим Score (Приоритет + Модификаторы потребностей)
   - Запускает соответствующий Executor

### Типы действий:

- **System Actions:** Автоматические (туалет, перерыв)
- **Tactic Actions:** Назначаемые игроком

### Основные действия персонала:

| Действие | Описание |
|---------|--------|
| WorkAtDesk | Работа за столом |
| CoverDesk | Прикрыть отсутствующего |
| DeliverDocuments | Перенос документов в архив |
| HelpConfusedClient | Помощь растерянному клиенту |
| Patrol | Патрулирование |
| CatchThief | Поймать вора |
| CleanMess | Уборка беспорядка |
| SystematizeArchive | Работа с архивом |

## Система Износа и Поломок

### Состояния прочности:

| Состояние | Прочность | Влияние |
|-----------|-----------|---------|
| **Целый** | 100-70% | Полная эффективность (1.0x) |
| **Потертый** | 70-30% | Сниженная (0.7x) |
| **Сломанный** | <30% | Не работает (0.1x) |

### Что подвержено износу:

- Рабочие столы (ServicePoint)
- Стулья ожидания (WaitingChair)
- Диваны отдыха (RestArea)
- Оборудование (Компьютер, Кофемашина)
- Окна и двери

### Источники деградации:

1. **Использование:** Клиент сел → -5, Клерк работает → -2, Диван → -10
2. **Время:** 0.5 durability/час игрового времени
3. **Вандализм:** Enraged клиенты ломают предметы

### Ремонт:

- **Микро-ремонт (Уборщик):** 10-30 сек, восстанавливает 30%
- **Макро-ремонт (Бригада):** Через документ → все предметы до 100%

## Система Беспорядка

### Типы беспорядка:

- **Мусор** — снижает скорость передвижения
- **Лужи** — снижает скорость, генерирует грязь
- **Грязь** — накапливается, влияет на комфорт

### Влияние:

- Клиенты с грязью под ногами быстрее злятся
- Сотрудники работают медленнее
- Страйки от проверяющих органов

### Решение:

- Уборщик убирает беспорядок
- Улучшение "Автомат с талонами" снижает хаос в очередях

## Система Приказов

### Каждое утро: выбор 1 из 3 случайных Приказов

**Типы:**

1. **Мандаты:** Нормы выработки ("День без ошибок")
2. **Баффы:** Улучшения параметров ("Кофе за счёт заведения")
3. **Экономические:** Поток денег ("День открытых дверей" — x1.5 клиентов)
4. **События:** ("День Пенсионера" — только бабушки)

### Применение:

- ClientSpawner и StaffController читают списки
- Применяют множители к формулам
- Секретные/нелегальные приказы (при высокой коррупции)

## Потребности Работников (доп.)

### Кулер и разговорчики:

- Работники подходят к кулеру → снижение стресса
- Несколько у кулера → эмуляция разговора

### Влияние потребностей на геймплей:

| Потребность | Эффект при критическом уровне |
|-------------|------------------------------|
| Bladder > 0.7 | Уходит в туалет |
| Energy < 0.3 | Замедляется |
| Morale низкая | Грубит клиентам |
| Frustration = 1.0 | Истерика или увольнение |
