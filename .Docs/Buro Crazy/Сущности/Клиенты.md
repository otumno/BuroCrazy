# Клиенты

---

**Цель фичи:** Вариативность геймплея. Игрок визуально считывает угрозу и реагирует.

## Общее описание

**Клиентская система** управляет всеми посетителями офиса — от момента спавна до выхода.

### Ключевые особенности:
- **Жизненный цикл**: Клиент проходит от спавна до выхода через несколько этапов
- **State Machine**: Машина состояний управляет поведением клиента
- **Терпение**: У каждого клиента есть таймер терпения, по истечении которого он уходит
- **Цели визита**: Разные цели ведут к разным зонам офиса
- **Архетипы**: Влияют на скорость, терпение и поведение клиента
- **Интеграция с зонами**: Клиенты используют LimitedCapacityZone для очередей
- **Grumbling**: Промежуточное состояние недовольства перед яростью

### Как клиент влияет на геймплей:
- Клиенты создают очередь — нужно назначать сотрудников к окнам
- "Сложные" клиенты (ярость, ворчание) требуют внимания
- Некоторые клиенты платят больше, некоторые создают беспорядок
- Ушедшие злые клиенты могут оставить негативный отзыв
- **Grumbling** даёт игроку ранний фидбек о недовольстве клиента

### Отличия от документации:
⚠️ Архетипы "Бабушка", "Суетун", "Мажор", "Пролаза" — **концептуальные**, в коде реализованы через `babushkaFactor` и `suetunFactor`
- Функция "VIP/двойная оплата" — **не реализована** в текущем коде
- Функция "пролаз без очереди" — **концептуальная**, prolazaFactor не используется активно

## Система Клиентов

### Жизненный цикл клиента

```
Spawning → AtRegistration → AtDesk → AtCashier → Leaving → Destroy
                ↓
         VisitToilet ──────────────────────→ Returning to Goal
                ↓
         WaitingForDocument → AtCashier → Leaving
                ↓
         InsideLimitedZone → DirectorService → Leaving

[Проблемные состояния]
├── Confused ──→ Выбор новой цели / Возврат
├── Grumbling ──→ Ропот/ворчание ──→ Enraged / LeavingUpset
└── Enraged ──→ 10 сек хаоса → Выход
```

### Клиентские состояния (ClientState)
- `Spawning` - Спавн
- `MovingToGoal` - Движение к цели
- `InQueue` - В очереди
- `WaitingForDocument` - Ожидание документа
- `AtRegistration` - У регистратуры
- `AtDesk1`/`AtDesk2` - У окон 1-2
- `AtCashier` - У кассы
- `InsideLimitedZone` - В зоне директора
- `Leaving` - Уход (успех)
- `LeavingUpset` - Уход (расстройство)
- `Confused` - Замешательство (потерял цель)
- `Grumbling` - **Ворчание/роптание (новое!)**
- `Enraged` - Ярость

### Система Grumbling (промежуточное недовольство)

**Назначение:** Дать игроку ранний фидбек о недовольстве клиента до того, как он перейдёт в агрессивное состояние.

**Логика перехода:**
1. Клиент накапливает стресс в очереди
2. При достижении индивидуального порога `grumblingThreshold` → переход в Grumbling
3. В состоянии Grumbling клиент периодически показывает мысли-ворчания
4. Если недовольство не устранено → при 100% терпения: Enraged (40%) или LeavingUpset (60%)

**Параметры в архетипе:**
| Параметр | Описание | По умолчанию |
|----------|----------|--------------|
| `grumblingThreshold` | % терпения для перехода в Grumbling | 0.5 (50%) |
| `grumblingFrequency` | Частота мыслей о недовольстве (0-1) | 0.5 |
| `canGrumble` | Может ли ворчать (false = сразу в Enraged) | true |
| `grumblingLines` | Список реплик ворчания | - |

**Влияние архетипов на Grumbling:**

| Архетип | Порог входа | Частота ворчания | Поведение |
|---------|-------------|------------------|-----------|
| **Суетун** (suetunFactor > 0.5) | Ниже (-15%×фактор) | Ниже (-30%×фактор) | Быстро начинает ворчать, но ворчит редко → быстро срывается в ярость |
| **Бабушка** (babushkaFactor > 0.5) | Выше (+15%×фактор) | Выше (+20%×фактор) | Долго терпит перед ворчанием, но ворчит часто и долго → терпеливо ждёт |

**Примеры:**
- Суетун с фактором 0.75: порог = 0.5 - 0.11 = 0.39, частота = 0.5 - 0.23 = 0.27
  - → Быстро (39% терпения) начинает ворчать, но редко (27%)
  - → Но быстро срывается в ярость

- Бабушка с фактором 0.75: порог = 0.5 + 0.11 = 0.61, частота = 0.5 + 0.15 = 0.65
  - → Медленно (61% терпения) начинает ворчать, но часто (65%)
  - → Но терпеливо ждёт обслуживания

## Архетипы

### Факторы влияющие на поведение:
- **babushkaFactor** (0-1): Замедляет, повышает терпение, медленнее ворчит
- **suetunFactor** (0-1): Ускоряет, понижает терпение, быстрее ворчит
- **prolazaFactor** (0-1): Склонность пролезть без очереди

### Характеристики:
- `totalPatienceTime` - Время до ухода
- `stressMultiplier` - Множитель стресса
- `noiseTolerance` - Толерантность к шуму
- `corruption` - Склонность к взяткам

## Behavior Tree для Клиентов

### Назначение

Behavior Tree (BT) — это модульная система поведения, которая заменяет/дополняет текущую State Machine. BT позволяет создавать гибкие и расширяемые паттерны поведения клиентов.

### Структура дерева

```
ClientRoot (Selector - пробуем стратегии по очереди)
│
├── MainGoal (Sequence - главный путь к цели)
│   ├── SetRegistrationGoal → MoveToRegistration
│   ├── JoinQueue → WaitInQueue (30s timeout)
│   ├── GetServed
│   ├── NeedCash? → MoveToCashier → AtCashier
│   └── LeaveSuccess
│
├── AlternativePath (Sequence - альтернативы при блокировке)
│   ├── QueueTooLong? → CutInLine → DirectorComplaint → LeaveUpset
├── GrumblingBehavior (Sequence - управление недовольством)
│   ├── IsGrumbling? → GrumbleSequence
│   └── PatienceZero? → Enrage / LeaveFrustrated
│
└── LeaveBehavior (Sequence - завершение)
    └── ShouldLeave? → MoveToExit → Leaving
```

### Типы узлов BT

| Тип | Узел | Описание |
|-----|------|----------|
| **Composite** | Sequence | Выполняет детей по порядку, Success если все успех |
| **Composite** | Selector | Пробует детей пока один не успех |
| **Composite** | Parallel | Выполняет всех детей параллельно |
| **Decorator** | Invert | Инвертирует результат |
| **Decorator** | Repeat | Повторяет N раз |
| **Decorator** | Timeout | Прерывает если > N секунд |
| **Decorator** | Condition | Проверяет условие |
| **Leaf** | MoveToGoal | Идёт к точке |
| **Leaf** | Grumble | Показывает недовольство |
| **Leaf** | Leave | Уходит |
| **Leaf** | Enrage | Выходит из себя |

### HeatLevel (уровни терпения в BT)

| Уровень | Терпение | Описание |
|---------|----------|----------|
| `Calm` | 0-40% | Спокойствие |
| `Grumbling` | 40-70% | Ворчание |
| `Frustrated` | 70-90% | Расстройство |
| `Enraged` | 90-100% | Ярость |

### Использование

```csharp
// Добавьте ClientBehaviorManager на префаб клиента
var behaviorManager = GetComponent<ClientBehaviorManager>();
behaviorManager.SwitchMode(ClientBehaviorMode.BehaviorTreeOnly);
```

### Режимы работы

| Режим | Описание |
|-------|----------|
| `StateMachineOnly` | Только старая State Machine |
| `BehaviorTreeOnly` | Только новая Behavior Tree |
| `Hybrid` | SM для действий, BT для решений |

### Преимущества перед State Machine

1. **Модульность** - легко добавлять/удалять поведения
2. **Расширяемость** - новые узлы без изменения существующих
3. **Читаемость** - дерево понятнее вложенных switch-case
4. **Гибкость** - легко создавать вариации для архетипов
