# Ручные проверки BuroCrazy

Актуально: 17 ноября 2026. Это план проверок, а не отчёт об их успешном прохождении.
Агент работает один; Play Mode и визуальные проверки выполняет владелец.

## Сначала — изменённые загрузка и найм

| Проверка | Действия | Ожидаемый результат и зачем |
|---|---|---|
| Загрузка с паузой | Из меню загрузить существующий слот; повторить после выхода из игры, стоящей на паузе | Экран загрузки исчезает. В логе подряд `[TransitionManager] Начало перехода`, `Сцена загружена`, `Переход завершён`, затем `[GameSession]`/`[Unveil]`. Проверяет устранение ожидания игрового времени при timeScale=0 |
| Новая игра | Создать новую игру в свободном слоте | Переход проходит до заставки дня и вступления/стола. Не перезаписывать нужный сейв ради теста |
| Постоянный утром | Во время активного утра нанять постоянного, закрыть панели, дождаться следующего периода | В текущем периоде ещё дома; в следующем появляется и начинает действие. Число периодов в маске соответствует рангу, без ручного расписания |
| Постоянный вечером | Нанять перед ночью | Выходит в следующем ночном периоде, продолжает смену через границу дня без второго спавна |
| Постоянный ночью | Нанять в последнем периоде календаря | Выходит в первом периоде следующего дня; нет дополнительного ожидания суток |
| Временный | Нанять утром, затем отдельно в предпоследний дневной период | Начинает со следующего периода, работает только оставшиеся дневные периоды; цена учитывает их количество; к концу дня удаляется из штата |
| Временный слишком поздно | Попытаться нанять, когда дальше только ночь | Найм недоступен, деньги не списываются |
| Повторные проверки смен | После найма несколько раз открыть/закрыть связанные панели, сменить период | Нет двойного выхода, двойного списания и нескольких таймеров опоздания |
| Сохранение после найма | Сохранить через выход в меню до первого выхода сотрудника; загрузить | Срок найма не потерян: загрузка в начале того же дня не выводит его раньше назначенного периода |
| Старый сейв | Загрузить копию старого слота с постоянным и временным сотрудником | Оба восстанавливаются, временный не остаётся навечно дома из-за отсутствующего дня работы |
| Конец смены | Дождаться окончания назначенных периодов | Сотрудник идёт домой и исчезает; на следующей смене снова действует, а не стоит с законченным executor |
| Стартовые кандидаты | Создать новую игру, открыть доску найма | До повышения доступны только стажёры; после карьерного открытия появляются нужные роли |
| Специализация | Нанять открытого карьерой регистратора/кассира | У персонажа один StaffController соответствующего типа; clerkRole совпадает с ролью, не остаётся Regular |
| Двойные клики в конце дня | Быстро дважды закрыть расписание или выбрать приказ | Ровно один переход, нет двойной награды за приказ; окно приказа исчезает до возврата к столу. Логи `[EndOfDaySequence]` идут 1→2→3→завершена |
| Геометрия после сохранения сцены | Осмотреть офис, двери и препятствия | Внешний вид и маршруты прежние: Unity пересериализовала встроенные Mesh при сохранении настройки найма |

Для каждого сбоя прислать: день/период найма, тип и имя сотрудника, что ожидалось и что произошло, полный `Editor.log` либо фрагмент от найма до сбоя со stack trace. Для визуальных проблем — скриншот. Не только последнюю красную строку.
Маркеры: `[TransitionManager]`, `[GameSession]`, `[Unveil]`, `[HiringManager]`, `[StaffShiftTrace]`, `[InternController]`, `[StaffController]`. `опоздание=-1` означает больничный; у нового сотрудника на первом выходе его быть не должно.

## Следующие пункты — после исправления соответствующих систем

| Область | Сценарии и критерии |
|---|---|
| Клиенты | У каждого есть цель визита; получить номер, пройти очередь и регистратуру, нужный кабинет/кассу, завершить цель и уйти. Проверить отсутствие специалиста и появление нанятого специалиста в следующем периоде |
| Экономика | Оплата обслуживания меняет кошелёк ровно один раз; зарплаты списываются; смена дня не восстанавливает стартовый баланс; загрузка берёт сумму из слота |
| Потребности | Клиент и сотрудник идут в туалет/на перерыв, освобождают занятое место, снижают потребность и возвращаются к задаче |
| Буйные посетители | Создать буйного: наблюдать конфликт с работником и посетителем, вмешательство охраны, ручное изгнание кликом; после ухода он не удерживает очередь/стол |
| Охрана | Патруль, открытие/закрытие двери, изгнание, возвращение к работе; отчёт создаёт видимую бумагу на столе |
| Приказы ПКМ | Портрет/имя/роль, доступные ролевые действия, немедленное прерывание, накопление стресса, замена и истечение приказа; прерывание обслуживания не теряет клиента или документ |
| HUD | Только сотрудники на смене, порядок выхода, цвет роли, туалет/стресс и время до конца назначенной работы сегодня; уход удаляет строку |
| Документы | Обработка видна у регистратора/клерка/кассира/архивариуса; документ летит клиент→стол→клиент; стажёр/офис-менеджер доставляет стопку в архив, включая переполнение |
| Уборщик | Мешок появляется при сборе, несётся к контейнеру, исчезает после выброса; проверить прерывание приказом |
| Ночное планирование | Статистика→Далее→смены→приказ→стол; не остаётся невидимый блок кликов или лишняя пауза; работа ночной смены продолжается после возобновления |

Наличие строк в этой таблице не означает, что соответствующие исправления уже внесены.

## Пункт 3: приказы и отмена (15.11)
1. ПКМ на каждой доступной роли: компактный портрет/имя/роль, общие и ролевые действия, недоступные действия выключены; закрытие мимо/ESC снимает ровно одну паузу.
2. Приказать туалет во время работы, затем отдых: начало немедленное, старое действие не возобновляется параллельно; стресс +5 за каждый приказ (с учётом естественного изменения).
3. Отменить перенос обычной стопки и проектной папки в пути; проверить общее число и данные документов, отсутствие занятого навсегда места архива. Повторить при полном архиве/заполнении исходного стола во время переноса.
4. Прервать обработку бланка во время полёта к столу, обработки и выдачи: клиент получает исходный бланк, повторное обслуживание возможно, лишней платы нет.
5. Прервать регистратора во время вызова и ожидания архива: талон снова доступен, клиент возвращается ждать. Прервать архивариуса/курьера и подмену стажёром: запрос/стол доступны повторно.
6. Приказ патруля живёт не дольше настроенного срока (по умолчанию 60 игровых секунд); пауза срок не расходует. После истечения AI решает сам.
7. Логи для диагностики: [StaffOrderTrace], [StaffActionTrace], [DocumentTransfer]. При ошибке приложить от выдачи приказа до следующего действия.

## Пункт 4: HUD
- Первый/поздний выход, опоздание и повторный выход: порядок соответствует реальному началу смены, не порядку найма; дома/больные/уволенные отсутствуют.
- Проверить портреты и цвета ролей, изменение шкал стресса/туалета, удаление строки после окончания смены, переход суток и загрузку.
- Время учитывает лишь оставшиеся назначенные периоды текущего календарного дня; на паузе не убывает, будущие сутки не прибавляются.
- Проверить 0/1/10+ сотрудников, прокрутку, длинные имена, разные разрешения экрана, отсутствие перекрытия важных кнопок правой панели.

## Пункты 5–6: ролевой цикл и ночь
- Клиент каждого типа: талон → вызов → регистратор → нужный кабинет/архив → касса → выход. В кассе сопоставить [ClientServiceTrace] с деньгами HUD, проверить однократность оплаты и отмену до оплаты.
- Потребности всех ролей: движение, статус, визуальный эффект, снижение потребности, физический возврат к рабочему месту, продолжение обслуживания. Прервать приказом на каждом этапе.
- Охрана: буйный клиент повышает стресс стоящих рядом; после разговора охраны или ЛКМ идёт к выходу; следующий нарушитель тоже обрабатывается. Два охранника не переключают дверь обратно; отчёты не пропадают при полном столе.
- Уборщик: видимый мешок от источника до контейнера, отмена в пути сохраняет мусор; повторный найм/повышение корректно подхватывает RoleData и визуалы.
- Повышение стажёра: сохранены имя, ранг, навыки, зарплатный долг, смена; в объекте ровно один StaffController, сотрудник остаётся в списке найма и HUD.
- Спавн: загрузка с районом, захват первого района, смена периода, повторное обновление потока, F10. Нет дублей волн и спавна старого периода ночью; [ClientFlowTrace] показывает причины нулевого потока.
- Ночная смена StartNight → EndNight → Morning: без повторного старта/болезни на границе суток, остаток HUD относится к текущему дню. Опоздание, пересечённое F10, не блокирует следующий день.
- Ночью дневной приказ заменяется после завершения экранов; разовая выплата не происходит на старом дне. Проверить пустой пул одноразовых приказов.

## Дополнение 17.11: совместимость и найденные пограничные случаи

| Проверка | Действия | Ожидаемый результат |

| Загрузка в середине периода | Сохранить через меню с деньгами, сотрудниками и частично выпущенной волной; загрузить | Сохраняются период/время, кошелёк, потребности и назначение первого выхода. | Старый перерыв стажёра | Дождаться самостоятельного перерыва/туалета, заменить приказ в пути | Корректные статусы, сброс потребности только после прихода, возврат к работе; нет параллельного движения |

Дополнительные логи: `[ArchiveRequestTrace]` (выдача), `[ClientServiceTrace]` (прибытие к провайдеру), `[StaffRoleTrace]` (повышение). Прислать полный Editor.log за сценарий с ожидаемым и фактическим поведением; успешная компиляция не заменяет эти проверки.

### Приоритетные проверки после исправления посещаемости
- Сохранить работающего сотрудника и загрузить: он не получает новый случайный больничный/опоздание. Отдельно сохранить больничный и загрузить в тот же день: болезнь остаётся; после смены дня разрешён новый расчёт.
- Сохраниться в середине опоздания: после загрузки ждёт только остаток, не весь первоначальный срок. Повышение роли ожидающего сотрудника не запускает таймер заново.
- Два стажёра на один перерыв клерка: подменяет один; после возвращения специалиста регистрация стола не пропадает. Отменить подмену во время движения клиента — он снова может получить обслуживание.
- Клиент начинает буянить или уходит во время обработки/оплаты: его не возвращают принудительно в обслуживание, счёт не проводится после ухода.
- Сравнить один игровой период при разных FPS и на паузе: `[StaffNeedsTrace]` меняется по игровому времени, на паузе значения стоят. Проверить частоту туалета/перерыва и влияние на доступность рабочих мест: после исправления расчёта потребности растут существенно быстрее прежнего бага.

### Повторный выход и явные цели
- Назначить две смены с коротким промежутком; переключить период, пока сотрудник идёт домой. После завершения ухода начинается актуальная смена, без ожидания ещё одного периода.
- Спринтер: сравнить скорость в двух последовательных сменах и после повышения роли. Бонус остаётся +30%, не умножается повторно.
- Создать принудительного клиента GetCertificate1 через катсцену/спавнер, затем специального посетителя с DirectorApproval: цель не заменяется случайной, стартовый документ соответствует цели. Подтип Form2C обслуживается как вторая категория. Для обычных клиентов цель видна в `[ClientFlowTrace]` и не меняется повторной инициализацией.

### 24.11 — места в кабинетах и туалете
- Два посетителя у зоны вместимостью 1: второй ждёт, пока первый идёт к месту и обслуживается; сотрудник не обрабатывает документы до прибытия первого.
- Клиент в туалете доходит до внутренней точки, проводит там время и освобождает её; следующий может войти. Ожидание архивного документа у регистратора удерживает место до направления дальше.
- Выдворить/прервать маршрут клиента на пути внутрь и у стойки: место доступно следующему. Удаление старого клиента после смены владельца места не выталкивает нового.
- Собрать Editor.log с [ClientZoneTrace] (DEBUG_ENABLED), [ClientServiceTrace] и [ClientFlowTrace]. Проверка логики уже пройдена через Tools/Checks/ClientZoneReservation.cs, но не заменяет проверку движения/очереди в игре.

### 24.11 — первый маршрут, прерывания и недовольство
- Новая волна: клиент после Spawning начинает двигаться к талону, затем к ожиданию/нужной зоне. Проверить цепочку [ClientFlowTrace], отсутствие неподвижного посетителя с уже выбранной целью.
- Прервать движение выдворением; отдельно прервать ожидание бланка. Старый маршрут/таймер не возвращает посетителя к отменённой задаче.
- VisitToilet после талона идёт к туалету, а не на стул в зале. Обычный посетитель временно посещает туалет: вызов в регистратуру ждёт его возвращения; приоритетная консультация тоже не выдёргивает его из другой зоны.
- Довести терпение до ворчания: стресс продолжает расти, затем клиент уходит либо буянит. После Confused и восстановления маршрута терпение снова расходуется. На паузе изменений нет.
- Клиент ушёл к следующему кабинету/выходу или стал буйным у стойки: предыдущая стойка не остаётся занята его CurrentClient, следующий посетитель обслуживается. Повторная очистка старого посетителя не снимает нового.
- Перекрыть путь к стойке/стулу/выходу: [ClientPathTrace] фиксирует недостижение, клиент не обслуживается издалека и не исчезает внутри здания. После открытия выхода попытка повторяется; при недоступном стуле освобождается его резерв.

### После прогона с зависшими талонами 2/5 и добавления статусов
1. Начать новый прогон: у каждого клиента, Директора и нанятого работника постоянно видны подписи. Пауза не скрывает их. Проверить читаемость при обычном приближении камеры, скоплении людей и открытом пузыре мыслей; настройка — Resources/UI/CharacterActivityStyle.asset.
2. Директор в регистратуре: вызвать двух клиентов подряд, впустить посетителя без очереди во время подхода первого. Стойка и её резерв принадлежат только одному; следующий ждёт. В ClientServiceTrace есть ticket и reserved desk.
3. Выдержать таймаут вызова: талон остаётся в общей очереди, после возвращения в зал клиент вызывается снова. Старый сотрудник/старый callback не очищает нового посетителя.
4. Увести Директора к другому столу во время ожидания/услуги. Клиент освобождает назначение и снова может получить обслуживание, остановленная услуга не продолжает выполняться отдельно.
5. Напряжённый вызванный клиент доходит до стойки без цикла идёт/ворчит каждые 0.2 с. При полном исчерпании терпения возможен штатный уход/срыв.
6. Статусы: регистратор/Директор показывают место и имя обслуживаемого; уборщик — задачу/перенос, охранник — текущую задачу, стажёр — доставку/подмену, потребности — отдых/туалет. При продвижении по маршруту подпись обновляется.
7. Провести клиента/работника/Директора по луже: подпись «Упал: поскользнулся на луже», после подъёма — актуальное действие. Отдельно проверить падение от неуклюжести, клинч и приказ во время движения. Подписи не перехватывают ЛКМ выдворения и ПКМ приказов.
8. Прислать Editor.log после нового прогона (не только строки ошибок). Сохранить лог до следующего перезапуска Unity: предыдущий прогон перемещается в Editor-prev.log.


### 25.11 — карьерный найм и ночной возврат (пункты 1–2)

1. Новая игра: только стажёры ранга 0. После открытия Хранителя печатей и обновления доски появляются регистраторы. После Смотрителя штата — уборщики, а у открытых ролей могут появляться ранги 1; до Казначея кассиров быть не должно. После Главы департамента допустим ранг 2. Опытный кандидат появляется по вероятности, не обязательно на каждой доске. Сохранить/загрузить карьеру и повторить. Логи: HiringAccessTrace.
2. Найм утром/днём: постоянный и временный выходят со следующего периода. Поздний временный оплачивает только оставшиеся до ночи периоды, в начале ночи исчезает из штата. Повторный клик по нанятому резюме не создаёт второго работника и не списывает деньги снова. Логи: HiringManager, StaffShiftTrace, Payroll.
3. Днём расписание не меняется; ночью F10 → статистика с «Далее» → расписание → выбор приказа → стол директора. До завершения выбора утро не наступает; после «Начать день» время идёт, панели и пауза не зависают. Обычное открытие бухгалтерии сохраняет «Назад».
4. Перед F10 отправить Директора к доске, двери, служебному столу или с бумагами в архив. После ночной цепочки он у своего стола, без старого маршрута/самопроизвольного открытия окон и без блокировки управления. Недоставленные бумаги видны на исходном столе, доставленные — в выбранной архивной стопке; переполнение не уничтожает остаток. Повторить при полном исходном столе и занятом основном архиве. Логи: EndOfDaySequence, DirectorDocumentTrace.

Проверки кода/ассетов выполнены вне Play Mode; клики, движение по реальным путям, паузы, падение во время перехода и сохранение в игровом прогоне ещё не подтверждены.


### 25.11 — приказы и HUD (пункты 3–4)

1. ПКМ по каждой роли: портрет, имя, роль и общие команды отдыха/туалета; охраннику доступен патруль, всем типам клерков — архив. Архивная команда неактивна для пустого стола и стола только с проектными документами, активна при наличии обычных бумаг. Проектные бумаги после переноса остаются на столе.
2. Во время обслуживания/патруля/переноски выдать приказ, затем сразу другой. Старое действие прекращается, клиенты/бумаги/резервы не теряются, стресс растёт за оба приказа и не откатывается при замене. Логи StaffOrderTrace. Через 60 игровых секунд незавершённый приказ истекает; пауза не тратит его срок.
3. HUD: нанять двух работников в разные периоды, дождаться выхода; порядок соответствует фактическому приходу. Перерыв не убирает работника из списка, конец смены убирает, повторный выход добавляет вниз. Цвет рамки соответствует роли, туалет/стресс меняются, таймер учитывает только оставшиеся периоды сегодняшнего дня. Повторить с ночной сменой и повышением роли.

### 25.11.2026 — обслуживание и локализация (игровой прогон)

1. Два соседних окна: разные посетители обслуживаются своими сотрудниками; уход/срыв/переназначение одного во время диалога или бумаги не затрагивает другого. В журнале `ClientServiceTrace` не должно быть повторной оплаты.
2. Оба типа бланков: рука → стол → сертификат в руку → один счёт → касса. Прервать приказом во время обоих перелётов: исходный бланк возвращается, денег/сертификата за прерванную работу нет.
3. Повторить ручным директором. Отойти/уйти в кабинет/завершить день во время обработки: нет зависшей бумаги, иконки, клиента или запертой стойки. Директор-кассир действительно пополняет кошелёк.
4. Архивариус/директор: обычные и overflow-стопки, недоступный шкаф, отмена на пути. Бумаги исчезают из исходной стопки только после подхода, не пропадают при неудачной доставке.
5. Сменить ru/en в настройках. Затронутые реплики, суммы оплаты и кнопка «Далее» переводятся. Проверить в игре читаемость TMP, переносы и иконку обработки поверх стола без перехвата кликов. Это начало поэтапной локализации, не перевод всего проекта.
